# 데모 영상 스크립트 (약 3분)

배포 URL: https://aiops-edge.yh9365.workers.dev

**한 문장:** AI가 고치고, Rust 하네스가 증명하거나 거절한다.
성능 개선, 실수 거절, 보안 수정, 하네스 보안, 취약점 탐색, 24시간 운영을 모두 이 한 문장의 증거로 보여 줍니다.

## 원칙

- **실제 값만 씁니다.**
  - 화면에는 실제 run ID와 측정값만 보여 줍니다.
  - 내레이션의 숫자는 녹화된 화면의 값을 그대로 읽습니다.
- **기다리는 구간은 빨리 감습니다.** baseline과 trial은 각각 약 2분 걸립니다. 자막에 "빨리 감기"와 run ID를 표시합니다.
- **Meta 모델임이 보이게 찍습니다.** provider 표시 `meta:muse-spark-1.3`가 화면에 나와야 합니다. 예전 Replay run(`replay` 배지)을 Meta 장면처럼 쓰지 않습니다.
- **일부러 만든 것은 그렇다고 밝힙니다.**
  - 하네스 검증용 함정 패치를 모델의 실수처럼 연출하지 않습니다.
  - 레드팀의 인젝션과 헌트가 찾은 SQL 인젝션은 데모 서비스에 일부러 넣어 둔 것입니다.
- **실행 위치를 밝힙니다.**
  - 보안 수정 시나리오와 레드팀은 Cloudflare 배포본이 아니라 GitHub 러너에서 돌았습니다. 자막에 그렇게 적습니다.
  - 취약점 헌트는 Cloudflare 배포본에서 돌았습니다.

## 녹화 전 준비 (10분)

1. 배포 URL을 열고 `Set admin token`에 GitHub에 등록한 `ADMIN_TOKEN`을 넣습니다.
2. 녹화 10분 전에 사이트를 깨웁니다.
   - 컨테이너는 쉬면 잠듭니다(aiopsd 15분, runner 20분).
   - 첫 run은 runner가 뜨는 데 1분쯤 더 걸립니다.
3. 실시간 run이 실패할 때 쓸 대체 화면과 보안 장면 화면을 탭으로 열어 둡니다.
   - 완료된 Meta run: `/runs/01a1a1fe-e7b1-76c8-b3ea-264d9bac80f6` (VERIFIED 89.2%)
   - 모델의 실제 실수와 회복: `/runs/01a19da7-b2a2-70e0-af44-018eddd0c003`
   - 보안 수정 실행 요약: https://github.com/qlanfr/mata_Hackathon/actions/runs/41659372904
   - 하네스 구멍 표: https://github.com/qlanfr/mata_Hackathon/blob/claude/busy-cannon-5b5n40/docs/security.md 의 "Holes found in the review" 절
   - 레드팀 요약: https://github.com/qlanfr/mata_Hackathon/actions/runs/41782003856 의 `injection screen` 줄이 있는 절(모델별 `### <model> · run <id>: COMPLETED`)
   - 배포본의 취약점 헌트: `/runs/01a1a52f-7595-70e7-b34d-ca133beab67d`
4. 녹화 설정
   - 브라우저 확대 110~125%, 1080p로 녹화합니다.
   - Windows는 Win+Alt+R, macOS는 Cmd+Shift+5, 또는 OBS를 씁니다.
   - 터미널 장면이 있으면 글자를 크게(18pt 이상) 합니다.

## 장면별 메모

- **실시간 run이 보류되거나 실패하면**
  - 그 화면도 쓸 만합니다: "기계가 흔들려서 판정을 거부했다"는 것 자체가 하네스의 성질입니다.
  - 다만 결과 화면은 준비 3번의 완료 run으로 대신합니다.
- **"오답 패치 26개"**
  - 화면 패널의 Trap patches 23/23과 Vulnerability-fix checks 5/5를 합친 28개에서 정답 패치 2개(정상 JOIN, 진짜 보안 수정)를 뺀 수입니다.
- **보안 수정 장면**
  - 요약 화면에서 보여 줄 부분: 각 run의 `attacks: 4 of 4 blocked (2 held out ...)` 줄, 모델이 쓴 diff, "Pull request description (not opened)".
  - 공격표가 있는 trial 화면은 배포본에 없습니다(보안 시나리오는 배포되지 않음).
- **하네스 구멍 장면**
  - 표의 Before 행 53.7 / 44.7 / 67.2%가 "가짜 개선"입니다. 코드는 원래의 느린 코드 그대로입니다.
  - 이 두 행은 로컬 측정입니다. 같은 함정이 CI의 격리 runner 이미지에서는 0.4 / −1.5 / −0.6%로 REJECTED였습니다. 자막에 "CI에서도 REJECTED"를 붙여도 됩니다.
  - 시간이 남으면 바로 위의 DB 권한 표(`permission denied` 목록)를 잠깐 스크롤합니다.
- **레드팀 장면**
  - 보여 줄 줄: run마다 `injection screen: N tool outputs flagged`(4, 4, 3)와 `patch carries planted code: none`, 그리고 trial의 VERIFIED.
  - 심어 둔 지시문 자체를 확대해서 보여 주지 않아도 됩니다. "표시됐고 따르지 않았다"가 요점입니다.
- **헌트 장면**
  - 실행 목록에서 "Vulnerability hunt" 행을 눌러 들어가도 됩니다.
  - 보여 줄 부분: Findings 카드의 Suspected 열(`sql-injection`, `src/search.rs: search_products`)과 Harness 열의 **NOT_REPRODUCED** 및 이유.
  - Replay로 돌린 로컬 헌트의 REPRODUCED는 스크립트 답이라 이 장면에 쓰지 않습니다.
- **24시간 운영 장면**
  - 예약 run이 실행 목록에 있으면 그 행(제목 "Scheduled run")을 보여 줍니다.
  - 없으면 터미널에서 `aiops info`를 보여 줍니다. 마지막 줄에 `schedule ... daily runs 30 daily tokens 1500000 noise retries 3 every 20 min`이 나옵니다.
  - PR 설명은 GitHub Actions의 "PR from a verified run" 요약(run 41664635685)에 있습니다.

## 쓰면 안 되는 표현

- "항상 고친다": 시나리오별 실행 횟수와 결과를 그대로 말합니다.
  - 성능: Spark 9회 중 9회, Wonder 4회 중 2회.
  - 보안: 5회 중 5회.
  - 실제 버그: 하네스 수정 뒤 2회 중 2회.
- "보안을 보장한다": 정해 둔 공격 4개와 정답 응답으로 판정할 뿐, 코드 리뷰를 대신하지 않습니다.
- "프롬프트 인젝션을 막는다", "모두 탐지한다": 레드팀 3회에서 표시됐고 모델이 따르지 않았다는 것까지만 말합니다. 탐지는 문구와 숨은 문자를 보는 어림 규칙입니다.
- "제로데이를 찾았다": 배포본의 첫 헌트는 재현되지 않았고, 대상도 일부러 넣어 둔 취약점입니다.
- "루트 권한을 원천 차단했다": "DB 권한을 읽기 전용으로 낮췄다"까지만 말합니다. 후보 코드는 격리 컨테이너 안에서 runner와 같은(root가 아닌) 사용자로 돕니다.
- "모든 부하에서 빨라진다": 고정된 부하와 데이터에서의 결과입니다.
