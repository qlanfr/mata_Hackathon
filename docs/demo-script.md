# 데모 스크립트 (약 3분)

원칙(기획안 12장):
- 화면에는 실제 실행 ID와 실제 측정값만 보여 줍니다. 아직 측정하지 않은 개선율은 성과로 말하지 않습니다.
- 실행 시간이 긴 구간(baseline 약 2분, trial 약 2분)은 녹화를 빨리 감기하고, 화면 자막에 "빨리 감기"와 run ID를 표시합니다.
- Meta API 키 없이 찍으면 화면의 `REPLAY` 배지가 그대로 보이게 두고, 내레이션에서 "모델 답변은 스크립트, 측정과 판정은 실제"라고 말합니다.
- 잘못된 후보(항목 누락) 장면은 하네스를 검증하려고 일부러 만든 사례라고 밝힙니다. 모델이 실수한 것처럼 연출하지 않습니다.

## 준비

- 배포 URL에서 관리자 토큰을 설정해 둡니다(`Set admin token`).
- 완료된 run을 하나 미리 만들어 둡니다. 생방송 대신 이 run을 보여 주거나, 새 run을 시작하고 기다리는 구간을 편집합니다.
- 하네스 검증 장면용으로 터미널에 아래 명령을 준비합니다(로컬 runner 기준).

```bash
./target/release/aiops-runner --pg-user postgres trial --patch scenarios/n-plus-one/candidates/known-bad-drops-items.json
```

## 보조 장면 (시간이 남으면)

- 실행 중 `Cancel run`: CANCELLING → CANCELLED. runner가 프로세스 정리를 확인한 뒤에만 확정됩니다.
- 같은 fingerprint의 알림 두 번: 두 번째는 같은 run에 병합됩니다.
- 측정 잡음이 크면 INCONCLUSIVE로 보류하고, 같은 패치를 한 번만 다시 측정합니다.
