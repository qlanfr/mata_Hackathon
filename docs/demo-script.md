# 데모 영상 스크립트 (약 3분)

배포 URL: https://aiops-edge.yh9365.workers.dev

**한 문장:** AI가 고치고, Rust 하네스가 증명하거나 거절한다.
성능 개선, 실수 거절, 보안 수정, 24시간 운영을 모두 이 한 문장의 증거로 보여 줍니다.

## 원칙

- **실제 값만 씁니다.**
  - 화면에는 실제 run ID와 측정값만 보여 줍니다.
  - 내레이션의 숫자는 녹화된 화면의 값을 그대로 읽습니다.
- **기다리는 구간은 빨리 감습니다.** baseline과 trial은 각각 약 2분 걸립니다. 자막에 "빨리 감기"와 run ID를 표시합니다.
- **Meta 모델임이 보이게 찍습니다.** provider 표시 `meta:muse-spark-1.3`가 화면에 나와야 합니다. 예전 Replay run(`replay` 배지)을 Meta 장면처럼 쓰지 않습니다.
- **일부러 만든 오답은 그렇다고 밝힙니다.** 하네스 검증용 함정 패치를 모델의 실수처럼 연출하지 않습니다.
- **실행 위치를 밝힙니다.** 보안 시나리오는 Cloudflare 배포본이 아니라 GitHub 러너에서 돌았습니다. 자막에 그렇게 적습니다.

## 녹화 전 준비 (10분)

1. 배포 URL을 열고 `Set admin token`에 GitHub에 등록한 `ADMIN_TOKEN`을 넣습니다.
2. 녹화 10분 전에 사이트를 깨웁니다.
   - 컨테이너는 쉬면 잠듭니다(aiopsd 15분, runner 20분).
   - 첫 run은 runner가 뜨는 데 1분쯤 더 걸립니다.
3. 실시간 run이 실패할 때 쓸 대체 화면을 열어 둡니다.
   - 완료된 Meta run: `/runs/01a1a1fe-e7b1-76c8-b3ea-264d9bac80f6` (VERIFIED 89.2%)
   - 모델의 실제 실수와 회복: `/runs/01a19da7-b2a2-70e0-af44-018eddd0c003`
   - 보안 수정 실행 요약: https://github.com/qlanfr/mata_Hackathon/actions/runs/41659372904
4. 녹화 설정
   - 브라우저 확대 110~125%, 1080p로 녹화합니다.
   - Windows는 Win+Alt+R, macOS는 Cmd+Shift+5, 또는 OBS를 씁니다.
   - 터미널 장면이 있으면 글자를 크게(18pt 이상) 합니다.

## 장면별 메모

- **실시간 run이 보류되거나 실패하면**
  - 그 화면도 쓸 만합니다: "기계가 흔들려서 판정을 거부했다"는 것 자체가 하네스의 성질입니다.
  - 다만 결과 화면은 준비 3번의 완료 run으로 대신합니다.
- **보안 장면**
  - 요약 화면에서 보여 줄 부분: 각 run의 `attacks: 4 of 4 blocked (2 held out ...)` 줄, 모델이 쓴 diff, "Pull request description (not opened)".
  - 공격표가 있는 trial 화면은 배포본에 없습니다(보안 시나리오는 배포되지 않음).
- **24시간 운영 장면**
  - 예약 run이 실행 목록에 있으면 그 행(제목 "Scheduled run")을 보여 줍니다.
  - 없으면 터미널에서 `aiops info`를 보여 줍니다. 마지막 줄에 `schedule ... daily runs 30 daily tokens 1500000 noise retries 3 every 20 min`이 나옵니다.
  - PR 설명은 GitHub Actions의 "PR from a verified run" 요약(run 41664635685)에 있습니다.

## 쓰면 안 되는 표현

- "항상 고친다": 시나리오별 실행 횟수와 결과를 그대로 말합니다.
  - 성능: Spark 9회 중 9회, Wonder 4회 중 2회.
  - 보안: 5회 중 5회.
  - 실제 버그: 하네스 수정 뒤 2회 중 2회.
- "보안을 보장한다": 정해 둔 공격 4개와 정답 응답 12개로 판정할 뿐, 코드 리뷰를 대신하지 않습니다.
- "모든 부하에서 빨라진다": 고정된 부하와 데이터에서의 결과입니다.
