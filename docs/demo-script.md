# 데모 스크립트 (약 3분)

배포 URL: https://aiops-edge.yh9365.workers.dev

## 원칙

- 화면에는 실제 run ID와 실제 측정값만 보여 줍니다. 내레이션의 숫자는 녹화한 화면에 나온 값을 그대로 읽습니다.
- 오래 걸리는 구간(baseline 약 2분, trial 약 2분)은 빨리 감기하고, 자막에 "빨리 감기"와 run ID를 표시합니다.
- 모델은 Meta Model API의 `muse-spark-1.3`입니다. 화면의 provider 표시(`meta:muse-spark-1.3`)가 보이게 찍습니다. 예전 Replay run(`replay` 배지)을 Meta 장면처럼 쓰지 않습니다.
- 하네스 검증용 오답 후보는 일부러 만든 것이라고 밝힙니다. 모델이 실수한 것처럼 연출하지 않습니다.

## 녹화 전 준비 (5분)

1. 배포 URL을 열고 `Set admin token`에 GitHub에 등록한 `ADMIN_TOKEN`을 넣습니다.
2. 컨테이너를 깨웁니다. 한동안 쓰지 않으면 컨테이너가 잠듭니다(aiopsd 15분, runner 20분). 첫 run은 runner가 뜨는 데 1분 정도 더 걸립니다. 녹화 전에 run을 하나 시작해 두거나, 녹화하면서 기다리는 구간을 잘라 냅니다.
3. 결과 화면용 완료 run(Meta 모델, VERIFIED): `01a19d86-d9d6-76d3-bced-54ae6d3475ec`
   - 실행 목록에서 열거나 `/runs/01a19d86-d9d6-76d3-bced-54ae6d3475ec`로 바로 갑니다.
   - 새 run을 시작해 실시간으로 찍어도 됩니다. 모델이 매번 같은 패치를 낸다는 보장은 없으니, 녹화한 run의 화면 값을 그대로 읽습니다.
4. 브라우저 확대를 110~125%로 맞추고, 1080p로 녹화합니다.
   - Windows: Win+Alt+R(Xbox Game Bar)
   - macOS: Cmd+Shift+5
   - OBS도 됩니다.

## 오답 후보 장면 (2:35–2:50)

배포된 화면에는 이 장면이 없습니다. Replay는 항상 정답 패치를 냅니다. 셋 중 하나를 고릅니다.

- **가장 권장:** 두 번째 Meta run(`/runs/01a19da7-b2a2-70e0-af44-018eddd0c003`)의 결과 화면을 씁니다.
  - Experiment 1은 모델의 실제 실수로 POLICY_REJECTED됐습니다(search 문자열 불일치, 실행 전 차단).
  - Experiment 2는 모델이 그 이유를 읽고 고쳐 VERIFIED를 받았습니다.
  - 연출 없는 오답 장면입니다.
- **권장:** GitHub Actions의 **Harness suite** 실행 요약 화면(함정 14개의 기대 판정 대 실제 판정 표)을 띄웁니다. 자막에 "직접 만든 함정 패치, runner 이미지 안에서 실행"이라고 답니다. 내레이션 예: "함정을 만들다 golden의 빈틈도 하나 찾았습니다. 항목 순서가 바뀐 오답이 통과하던 것을 케이스를 추가해 막았습니다."
- `docs/plan.md` 1일차 표(REJECTED · POLICY_REJECTED · INCONCLUSIVE)를 화면에 띄우고 "로컬 측정"이라고 자막을 답니다.
- Meta를 연결한 뒤 모델이 실제로 틀린 후보를 내면, 그 REJECTED 화면을 씁니다. 연출 없이 생긴 장면이므로 가장 좋습니다.
- 이 장면을 빼고 결과 화면 설명을 늘립니다.
